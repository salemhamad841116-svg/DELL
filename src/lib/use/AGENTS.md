# Market Compass engine rules (src/lib/use)

- Phase 1 data layer is frozen: all historical data goes through `fetchHistorical` (providers.server.ts) → coverage.ts → calendar.ts; later phases consume it, never rewrite it. Why: verified pipeline, single source of truth.
- Databento futures use continuous `X.v.0` symbology with per-bar instrument_id; absent OHLCV minutes are classified via Trades schema (NO_TRADE_INTERVAL vs TRUE_DATA_GAP). Why: OHLCV is trade-derived.
- Strategies execute only via StrategyIR (src/lib/use/strategy/: pine.ts → ir.ts → executor.ts → backtester.ts); unsupported constructs return UNSUPPORTED_SEMANTIC with line:col, never generic substitute logic. Why: strategy truth.
- Every backtest run is stored in use_backtest_runs with strategy hash, dataset hash, coverage report id and trades hash. Why: reproducibility.
- XAUUSD is spot (OANDA), never mapped to GC futures. Why: no instrument mixing.
- Golden semantic suite lives in src/lib/use/strategy/golden.test.ts with real-candle fixtures in __golden__/; expectations change only via UPDATE_GOLDEN=1. Why: every build must reproduce exact trades.
- request.security uses confirmed HTF buckets built from the chart candles (value = last bucket whose end ≤ chart bar close); lookahead_on allowed only as expr[n≥1] (value of the current bucket, reads completed buckets only); >1h HTF outside crypto is UNSUPPORTED_SEMANTIC except forex 1D (17:00 New York sessions). Why: no HTF leakage.
- Indicator→Strategy conversion lives in src/lib/use/strategy/convert.ts (+ convert.functions.ts): detected rules are suggestions only, generated copies store parent_indicator_id/source_indicator_hash/generated_strategy_hash and start draft/UNVERIFIED; unsupported options are BLOCKED, never approximated. Why: lineage + no invented logic.
- Convert-to-Strategy is ACCEPTED/FROZEN: change only for a reproducible bug. Why: user acceptance.
- Pine parity certification lives in src/lib/use/strategy/parity.ts: TradingView "List of trades" CSV (UTC) vs engine trades; PARITY_PASS only with zero missing/extra/direction mismatches and zero time deltas. Why: Phase 2 completion gate.
- No MQL5/Python/TS adapters until PINE_SEMANTIC_ENGINE = VERIFIED; adapters only compile to StrategyIR, never execute user code. Why: user priority + safety.
- Next Candle Forecast lives in src/lib/use/forecast/core.ts (+ forecast.functions.ts): uses indicator() values directly as features (no orders), predicts only from a fully closed source bar, one frozen row per symbol/timeframe/indicator_hash/target_ts in use_predictions (mode NEXT_CANDLE, DB trigger blocks edits), scored once after target close. Why: primary product goal, no repaint.
- Next Candle production runs only in the backend worker (src/lib/use/forecast.server.ts via /api/public/forecast-evaluate, pg_cron every minute, single-flight lease in use_worker_state, auth by DB-stored token); browser only displays persisted rows. Unique key symbol+timeframe+target_ts+model_version+indicator_hash. Why: forecasts must not depend on an open browser.
- Next Candle Forecast is fully independent of Strategy Conversion: INDICATOR_ONLY scripts feed forecasts directly (UP/DOWN/NEUTRAL/NO SIGNAL + scoring) with no BUY/SELL/EXIT/TP/SL/strategy.entry requirement; conversion is opt-in only. Why: user requirement.
- Crypto routing is CRYPTO_ROUTING in providers.server.ts (currently twelvedata; Binance = BLOCKED_BY_SERVER_REGION). Twelve Data crypto = its own USD pairs (BTCUSD), never mapped from USDT symbols. Why: no silent substitution / instrument mixing.
- Next Candle blocks with BLOCKED_PROVIDER_DELAYED when more than half the target bar has elapsed at generation time. Why: forecast must target a genuinely future close.
- TradingView has two independent modules: Pine Code Generator (src/lib/use/strategy/pinegen.ts + tvpine.functions.ts generatePineCode; indicator()/forecast only, frozen logistic coefficients over Pine-exact features, output re-validated and re-executed through the engine) and Strategy Tester Parity (parity.ts + runTvParity; strategy() runs only). Why: user must never convert an indicator to get TradingView code.
- Pine Code Generator trains on history only: if the live fetch is not complete it uses stored bars from the SAME provider, trimmed to the newest gap-free segment (calendar-aware), and reports mode/samples/warm-up; live freshness is the forecast worker's job. Twelve Data daily-credit 429 backs off until 00:00 UTC. Why: training ≠ live freshness, no provider switching.
- Next Candle reliability lives in src/lib/use/forecast/reliability.ts (pure: embargoed walk-forward, calibration, Wilson CI, PSI, signalGate, forwardStats); model registry use_nc_models (CANDIDATE/VERIFIED/DEGRADED/RETIRED) holds validation evidence — directional calls require a VERIFIED row, replacements need explicit promotion, healthCheck runs every worker tick. Why: reliability must be measured, never assumed.
- Worker quota guard: no provider call until the next source bar closes, none while the market is closed, retries throttled; scoring reads same-provider stored candles first. Why: Twelve Data 800 credits/day.
- Next Candle calibration = multinomial matrix scaling (fitTri in forecast/reliability.ts) fit on the chronological validation split only; model nc-logit-2.1.0. Why: one-vs-rest bins were miscalibrated (ECE 0.127).
- Unapproved setups store an experimental shadow call in gate.shadow at prediction time (user sees NO SIGNAL); model approval needs validation PASS + ≥300 scored shadow directional calls with Wilson CI low > baseline and ECE ≤ 0.10. Why: approval from genuine forward evidence only.
- Historical Pattern Analyzer lives in src/lib/use/pattern/ (analyzer.ts pure, pine.ts export) + pattern.functions.ts: levels are the indicator's own bar-by-bar series; same-bar source+target is resolved only with real 1m candles, else AMBIGUOUS (excluded); frozen rows use mode NEXT_CANDLE with model_version pattern-freq-1.0.0 so the worker scores them. Why: no lookahead, no invented intrabar order, reuse the immutable ledger.
- Pine front-end supports user-defined types (reference-semantics objects, field read/assign, Type.new), switch expressions, int()/float()/str.tostring()/str.format_time(); statement-form switch, array fields and switch case blocks stay UNSUPPORTED_SEMANTIC. Why: TradingView v6 parity without guessing.
- Pine generator model (nc-pine-logit-2.0.0): indicator columns that are absolute epoch time / bar index become minutes/bars-since; monotone counters dropped; 60/20/20 + embargo with multiclass calibration; Pine shows NO SIGNAL on missing input, wrong symbol/timeframe, or failed OOS calibration. Why: absolute time/index features do not generalise and uncalibrated probabilities must not be displayed.
